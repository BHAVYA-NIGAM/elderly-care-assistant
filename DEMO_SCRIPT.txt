[1:00 — ARCHITECTURE]
(show assets/architecture_diagram.png)
Let's walk through the architecture of how a user request flows through our system.
(pause)
First, every message enters the "security_checkpoint" node, which acts as a safety gate to scrub PII, block prompt injection, and detect medical emergencies.
If a prompt injection is detected, it is immediately routed to the "security_event_node" and blocked.
If a medical emergency is detected, it bypasses the system entirely via the "emergency_event_node" to give direct emergency instructions.
Clean messages pass to our "orchestrator" agent, which coordinates all Specialist sub-agents.
For routine, appointment, or meditation queries, the orchestrator delegates to our "routine_scheduler" sub-agent.
For health vitals or symptom tracking, it delegates to our "health_logger" sub-agent.
Both sub-agents connect to our out-of-process MCP Server to read and write records from the database.
If a specialist attempts to perform a write operation—like booking an appointment or logging vitals—the "check_sensitive_action" callback intercepts the call and routes to the "human_review_node".
This node pauses the workflow and asks for human caregiver confirmation before finalizing any database changes, ensuring absolute safety.
Finally, the results are formatted and displayed to the user via the "final_output" node.
